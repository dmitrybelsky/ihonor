# Ограничения решения

Честный список того, что **не работает** или работает с оговорками. Основано на
реверс-инжиниринге Phase 0 (см. `docs/spike/`).

## 1. Вложения (attachments) — НЕ синкаются в HONOR

Самое крупное ограничение.

- **iCloud → HONOR: невозможно.** Подтверждено спайком:
  - desktop HonorWorkStation **не имеет UI вставки файлов** — в тулбаре только
    форматирование текста (Bold/Italic/.../Alignment);
  - скрытый `icon-insert-img` лежит в мёртвом/мобильном коде (`ixRbar` не всплывает);
  - **paste картинки** (Cmd+V) в редактор не вставляет вложение;
  - прямой insert в БД/облако заблокирован (device-bound крипта + integrity-check).
- HONOR-заметки технически **поддерживают** вложения (таблица `attachment`: pdf/jpg/wav/json),
  но они приходят только с телефона/облака; добавить новое извне нельзя.
- **HONOR → iCloud:** выполнимо в принципе (Notes.app умеет attach), но не реализовано.

Итог: синкается только **текст** (заголовок + тело). Вложения переносите вручную, либо
извлекайте их текст и дописывайте в тело (не реализовано).

## 2. HONOR write = UI-автоматизация (хрупко)

Прямая запись в облако HONOR **невозможна**: device-enrollment + token-binding
(401 на replay) + DB-integrity tamper-detection. Поэтому запись идёт через драйв
самого приложения:

- Требует **запущенный залогиненный HonorWorkStation** с `--remote-debugging-port=9222`.
- **create/update**: CDP (`Input.insertText`, React-сеттеры) — зависит от CSS-селекторов
  (`.newNoteButton`, `textarea.noteTitleText`, `.app-note-editor-01`); обновление app
  может их сломать.
- **delete**: реальные OS-клики `cliclick` (CDP-синтетика/AX не триггерят нативное
  контекст-меню). Требует **Accessibility**, окно на переднем плане, фиксированную
  геометрию (frameless: screen = `window.screenX/Y` + viewport). Чувствительно к ресайзу/
  позиции окна. Activate приложения — по имени процесса `Hihonornote` (не `HonorWorkStation`).
- Запись не headless: при заблокированном экране/спящем app — ненадёжна.

## 3. iCloud через Notes.app

- Нужен **локальный Mac** с залогиненным Notes.app.
- Аккаунты с **Advanced Data Protection** отдают зашифрованный контент — не поддерживается.
- Удаление детектится по исчезновению из живых папок (заметка уезжает в «Recently Deleted»).

## 4. Конфликты и точность

- При правке с **обеих сторон** — `conflict-copy` (создаётся копия с тегом), без merge.
- Кросс-системные `mtime` недостоверны → **не** last-writer-wins.
- HONOR **обрезает длинные заголовки** (~50 симв.) → сопоставление по факту хеша
  сохранённого контента, не по запрошенному.

## 5. Fidelity

- Только плоский текст. Теряются: rich-форматирование, рукопись (HONOR type=6),
  чек-листы, таблицы, вложения.

## 6. Крипто/протокол-константы

- `AES_KEY`/`KEY_MATA`/nid в `dbkey.py` и реверс облачного протокола в
  `honor/cloud_client.py`/`crypto.py` — артефакты реверса конкретных версий app.
  Обновление HonorWorkStation может их изменить → деривация ключа/чтение БД сломается.

## 7. Прочее

- Один iCloud-аккаунт и один HONOR-аккаунт за раз.
- Только macOS.
- Системный `pip` может быть сломан (pyexpat) — используйте `uv`.
- Зависимость от внешних бинарей: `node@20`, `cliclick`, `osascript`.
